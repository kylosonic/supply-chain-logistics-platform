## 1. Ground-truth decisions (locked for @build; deviations require @architect sign-off)

1. **Copy lock matrix.** Strings marked **[EXACT]** below must appear byte-identical in code and tests (subject only to HTML entity encoding for quotes/dashes in SSR output — tests assert the decoded text). Strings marked **[COPY-TEAM]** are direction-locked (meaning, tone, claims) but wording may be adjusted by a copy pass before launch; @build ships the blueprint wording. NB-36.2's hero paragraph and the partial-payment story are locked verbatim from the behavior docs, NOT paraphraseable at build time.
2. **Multiple identical "Start free" CTAs are compliant; any other CTA label is not.** The single-CTA rule (§13, NB-46.3) forbids *competing* primary actions. The nav button, hero button, and final CTA all reading "Start free" → `/launch` are one CTA repeated (same label, same destination). Forbidden labels site-wide as primary actions: "Launch FreightPilot", "Create workspace", "Launch your workspace", "Start a workspace", "Explore the platform", "Explore the AI stack", "Open control tower", "Review docs", "Get desktop", "Download desktop", "Contact Sales", "Choose Starter", "Choose Scale", "Talk to sales", "See pricing", "Book a demo". Footer and nav *links* (non-button) are navigation, not CTAs; but the footer's "Contact Sales" primary-styled button is removed (becomes a plain "Contact" text link).
3. **Framer-motion on the home page = exactly one entrance animation.** The single allowed animation is a mount-time fade+rise on the hero headline (`m` element with `initial`/`animate`, no `whileInView`, no repeat). Everything else on `/` is static or CSS-transitioned. `motion-section.tsx` is REMOVED from the home render path (7 instances today — each is a scroll-triggered `whileInView` reveal, a direct NB-42.5 violation) but REMAINS for `/platform`, `/technology`, `/launch`, `/pricing` (NB-45.2 explicitly permits heavier components on non-home routes). The "How it works" expand/collapse uses a CSS grid-rows transition, not framer-motion (so it never counts against the one-animation rule). `site-chrome.tsx` loses its `useScroll`-driven nav scale and its back-to-top framer animation (scroll-triggered motion — removed entirely); the mobile-menu `AnimatePresence` stays (user-initiated interaction, not scroll-triggered). Regression guard: home SSR HTML must contain exactly one element with `style="opacity:0..."`-style initial state (the hero entrance) — asserted by test.
4. **Weight budget enforcement = deterministic post-build script + manual 3G devtools step.** Primary automatable gate: NEW `apps/product-web/scripts/check-bundle-budget.mjs` run after `next build` (npm script `check:bundle`). It parses `.next/build-manifest.json` for each of the 6 routes, sums the **raw (uncompressed) byte sizes** of every referenced JS chunk, adds `.next/static/css/*.css` totals and `.next/static/media/*` (self-hosted next/font woff2) totals, and exits non-zero if any route's sum ≥ 1,200,000 bytes. Raw-size-≤-budget is the conservative proxy for the 1.2 MB transfer budget (gzip transfer is always smaller). The 3G `LoadEventEnd < 3s` criterion (NB-42.2) cannot be automated in vitest/node — it is a documented manual devtools step (Network panel, 3G 400 kbps preset) in the PR checklist, with the measured per-route totals recorded in the PR description. Cheap regression net in vitest: SSR HTML length caps per route (home ≤ 120 KB rendered HTML).
5. **Analytics: none exist; nothing to lazy-load.** Verified by grep — `apps/product-web` has zero `next/script`, zero third-party analytics. NB-42.7 is satisfied vacuously. Phase 5 adds NO analytics (instrumentation is DEFERRED-08 scope). The PR checklist records this finding; any future addition must use `strategy="lazyOnload"`.
6. **Fonts: verified compliant, no change.** `src/app/layout.tsx` already loads exactly Inter + Space Grotesk via `next/font/google` (`subsets: ['latin']`, CSS variables), `globals.css` has no `@import`/`@font-face`, tailwind maps `--font-inter`/`--font-space-grotesk`. NB-42.6 satisfied by construction. PR checklist verifies `.next/static/media/` contains only these two families.
7. **`/launch` wiring (NB-46.5).** The form calls `POST {NEXT_PUBLIC_PLATFORM_API_URL}/auth/company-signup` — platform-api ONLY. Sample seeding is ALREADY triggered server-side by that call (Phase 4, `auth.py` line 212) — no client seeding code. On HTTP 201: show an honest success state ("Workspace created — sample data loaded.") and redirect immediately via `window.location.assign(NEXT_PUBLIC_APP_CONSOLE_URL || 'http://localhost')` (same source as `site-content.externalLinks.console`); the ops console bootstraps the session from the `supply_chain_token` cookie (`AuthContext` → `/auth/me` → `/`) when same-site, otherwise lands on its existing `/login` (which already instructs new workspaces to sign up on the product site).

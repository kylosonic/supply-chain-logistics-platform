Working and verified

  • Signup to first route plan. A new company workspace is created, seeded with sample operational data, and the first optimisation returns a real plan — 21.07 km, 31.61 ETB — persisted to run history.
  • Multi-tenant isolation. A second organisation cannot list, read or mutate the first organisation's rows. Cross-tenant reads answer 404, never 403, so record existence is never leaked. Pinned by a two-organisation regression suite.
  • Cashflow operations. Receipt ingestion, invoice matching, wallet credits, disputes, and reversals that are themselves audited and undoable.
  • Commercial controls. Subscription tiers, server-side usage metering with threshold events at 80%, 100% and overage, and bring-your-own-key provider management with encrypted storage.
  • Release discipline. Hash-verified dependency lockfiles, and CI running tests, lint, type-check, production builds and dependency audits on every push.

Engineering posture

  • Security audit completed and remediated. An independent audit found one critical and six high findings — including a committed placeholder signing key and a cross-tenant authorisation gap. All are remediated, with the remediation pinned by tests.
  • Four deployable surfaces. FastAPI platform API, React operations console, Next.js product site, and an Electron desktop shell.
  • Every deployed dependency audited clean. A full audit of the shipped dependency set for all three web surfaces now reports zero known vulnerabilities. That includes a Next.js 14 → 16 upgrade undertaken specifically to clear a build-chain advisory that no patch-level bump could reach.
  • ~20,000 lines across backend and frontend, with a contract-driven build: behaviour written first, then implementation, then verification.

Stated plainly — what is not finished

  • Pre-revenue. There are no paying customers yet. The product is built and verified; commercial validation is what this program is for.
  • The hosted production database needs its credentials reissued. The platform code and schema are verified working end to end; the hosted environment's database connection is the outstanding item before the public site accepts signups again.
  • No signed desktop installer yet. The Electron shell runs from source; a signed, auto-updating installer is planned work.
  • One open human verification gate. Confirming CBE and Dashen transfer fee schedules in the 5,000–50,000 ETB band against a ±1,000 ETB tolerance. This blocks paid launch, not the product.
  • Dev-only tooling advisories. The test runner and dev server (vitest, vite) carry advisories that need major-version migrations. Neither is shipped to users — they are build/test tooling only — so they are tracked rather than blocking release.
